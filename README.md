# GitHub 확장 관리자 1.0.1

## 설치
1. 마리나라 Settings → Addons → External Extensions에서 이 ZIP을 가져옵니다.
2. 코드와 Full page access 권한을 검토하고 실행합니다.
3. Settings → Addons → External Extensions의 **확장 폴더 가져오기** 아래에 있는 **GitHub 확장 관리** 버튼을 누릅니다.

외부 확장 설치가 이미 허용된 환경을 전제로 합니다. 원격 접속에서 관리자 접근이 필요한 경우 마리나라의 기존 Admin Access 설정을 사용합니다. GitHub 계정·비밀번호·토큰은 요청하지 않습니다.

## 사용
- 새 설치: GitHub 저장소 기본 주소 입력 → 패키지 찾기 → 대상 선택 → 내용 확인 → 설치.
- 기존 ZIP 설치본: 해당 확장의 GitHub 주소 연결 → 대상 확인 → 연결. 같은 이름·실행 방식인지 검사하며, 연결만으로 코드를 바꾸지 않습니다.
- 개별 업데이트: 해당 확장 **업데이트 확인** → 업데이트 보기 → 업데이트 설치.
- 전체 확인: 연결된 확장을 순서대로 확인합니다. 접근 불가 항목을 건너뛰며 자동 설치하지 않습니다.
- 설치/업데이트 뒤에는 마리나라 기본 외부 확장 화면에서 새 코드를 검토하고 실행합니다.
- 업데이트 후 **페이지 새로고침**으로 이전 코드의 실행과 화면에 남은 상태를 정리하세요. 전체 페이지 확장은 서버에서 비활성화해도 이미 실행한 부수 효과를 완전히 회수할 수 없습니다.
- 이전 코드 복구는 본체의 리비전을 사용하며 다시 승인이 필요합니다. 데이터 형식까지 과거로 복구하지 않습니다.

## 지원 범위
공개 GitHub 저장소의 manifest.json과 지정된 JS/CSS, 저장소에 커밋된 .personal-extension.zip, 최신 정식 릴리스의 ZIP 자산을 대상으로 합니다. 후보가 여러 개면 선택합니다. ZIP에는 manifest.json이 하나 있어야 합니다. 브랜치는 기본 브랜치를 사용합니다. 릴리스 자산은 브라우저 CORS 정책에 따라 직접 다운로드가 차단될 수 있으며, 이때 저장소 매니페스트 방식을 선택하거나 기존 파일 가져오기를 사용하세요. 인증 우회나 외부 프록시는 사용하지 않습니다.

GitHub 조회는 수동·비인증 방식입니다. 비공개/삭제/접근 제한은 오류 상태로 구분하며 로그인 창을 띄우지 않습니다. GitHub의 비인증 조회 한도에 걸리면 시간이 지난 뒤 다시 확인하세요. 업데이트는 실행 코드와 권한 해시를 비교합니다. 버전 번호만 바뀌거나 README만 바뀐 경우 코드 업데이트로 표시하지 않습니다.

기존 확장 ID와 저장 데이터를 유지합니다. 현재 코드에 로컬 수정이 있으면 덮어쓰기 경고를 표시합니다. 패키지 이름·실행 방식이 바뀌면 교체를 차단합니다. 다운로드는 변경 불가능한 Git blob을 사용하며, ZIP은 최대 8MiB/200개 파일로 제한합니다. 관리 확장 자체는 기본 임포트 화면에서 업데이트하세요.

## 검증과 한계
- Marinara Engine main c56501495a8baf76c258e76534c8728a9b7859bb의 확장 API·해시·저장 서비스 구조를 확인했습니다. 모든 구버전 호환을 보장하지 않습니다.
- 단위 테스트 7개 통과: URL/경로, 권한, 파일 순서, 해시 일치, ZIP 제한, 접근 불가 및 비인증 요청, 고정 Git blob 다운로드.
- DOM 모의 호스트 테스트 통과: 설치, 확인만 할 때 무변경, 비활성화 후 업데이트, ID/데이터 보존, 승인 해제, 비공개 건너뛰기, 적용 실패 시 이전 코드 보존, 승인 API 미호출, 종료 정리.
- 실제 공개 f-en-rep/Side-B에서 1.8.0 매니페스트와 코드를 읽고 해시 계산 완료.
- 실제 마리나라 서버에 설치하거나 모바일 Chrome에서 실행한 검증은 아직 하지 않았습니다. Chromium 다운로드 실패로 브라우저 화면 테스트는 미완료입니다.
- 다른 탭에서 동시에 같은 확장을 편집하지 마세요. 본체 API에는 조건부 갱신 계약이 없으며 이 확장은 적용 직전 코드 변경을 확인하지만 모든 동시 갱신 경쟁을 막을 수는 없습니다.
- 다운로드/검증 실패는 기존 확장을 변경하지 않습니다. 비활성화 후 적용 실패는 비활성 상태로 남습니다. 통신이 끊긴 경우 목록을 새로고침해 실제 적용 상태를 확인하세요.

## 소스
source 폴더에 원본과 테스트가 포함되어 있습니다. npm ci 후 npm test, npm run build, node lifecycle.mjs로 재현할 수 있습니다. browser-check.cjs는 Playwright와 Chromium이 별도로 필요합니다. 번들에는 fflate와 @noble/hashes가 포함되어 있으며 THIRD-PARTY-NOTICES.txt에 라이선스를 첨부했습니다. 실행 시 CDN 라이브러리를 로딩하지 않습니다.
